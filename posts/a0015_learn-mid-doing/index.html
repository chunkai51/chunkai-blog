    干中学？如何干？怎样学？

    March 26, 2026 · Chunkai

    问了各位教授、同学、博主，我算是对应该怎么学 agent 开发有了一个清晰认识，简单来说就是：

    • 学会一门最好跟 ai 关系密切点的语言，成为使用这门语言的工程师
    • 用 coding agent 开发
    • 开发 agent 赋能的产品

    做到这三点，你就成为了 agent 工程师，厉害吧。

    而我呢，大概一点都算不上，却希望在五月前攒出一份 agent 工程师的简历，难度可想而知。

    盘一盘我现在会什么：#

    • 掌握 Java SE
    • 了解 python 基础语法以及常用第三方库的使用
    • 了解 Claude Code，Codex 等 AI 工具的使用
    • 使用过 OpenAI Agent SDK
    • 知道 Web 开发
    • 听说过 MySQL 之类的东西

    天哪，好清澈，给自己逗笑了。也就 Java 是有点信心的东西，结果这语言还似乎跟 AI 没什么关系。

    就算熟练掌握某个语言又能如何呢？AI 不随便都能写出更规范的代码？这也正是我们这代学生的困境吧—— AI 让资深的工程师能够利用工具，提高效率，拉开与初级工程师的差距；让初级工程师能够迅速转换方向到热门领域；却全面地让我们失去了价值，甚至还要腐蚀我们的自学与思考能力，缩减本就不多的留给我们的岗位。而也许真正重要的思想、设计，学校还不教，只能在岗位上学……简直是死结。

    希望在哪里#

    要说我们的优势，大概也就是年轻、有体力，也许思想先进些？说出来我都不信，但也许就好像 LLM，输入给我们的是前人所拥有的上下文再加上前人创造的上下文，那我们就理应比前人更聪明。

    我们欠缺的，技术基础，应该利用 AI 迅速补充；经验，应该在开发项目的过程中形成，形成的是更先进的 “Agentic” 经验。学习的方式，就应该是所谓的 “干中学”。

    如何干？如何学？#

    三个字太泛，听起来很有道理，但具体么实践呢？

    拿我来说，我需要尽快成为称职的 agent 工程师，那么我就要熟练掌握 python 后端开发体系，掌握 python 语言，搞懂主流 Agent 框架，读懂成功的 agent 项目的代码，复现/设计出自己的 agent 项目。

    那么，在快速学完 python 语法后，我就应当开始“干”，写学生管理系统来复习面向对象、写含有 Web 界面的项目来体会前后端的配合，写些自己喜欢的东西探索这个语言的特点。至于那些数据库、中间件、第三方库、设计模式，都先只需要了解皮毛，在过程中遇到什么问题，就去学习什么，基础语法熟练后可以大胆使用 coding agent，在构建项目的同时，单独开一个线程来询问、学习不明白的部分。这就是“干中学”，在 AI 对于这些有公开文档的技术掌握程度一定远高于我的前提上，AI 就是最好的老师和协作者。

    在学习 agent 时，更是如此。这些东西底层很简单，更新又快，大概理解后就可以完全放心地交给 coding agent 来做。这时候要注意开始探索 coding agent 工具本身的能力，一方面这对学习和开发效率有显著提升，另一方面 coding agent 工具本身就是成功的 agent 产品，学习它们的工作方式对形成自己的设计思路是很有帮助的。于是，理想状态中，我们能在学会 agent 框架与设计思路的同时，做出一个合格的 agent 产品。

    总结来说，“干”的是主流的或自己想做的项目，“学”的是“干”的过程中暴露出的缺少的技术、认知。找对“干”的方向，不想当然，不对 AI “外行指挥内行”；保持“学”的态度，不完全放任 AI 来 “vibe coding”。应该就能达成目的。
