    LLM 的评估方法

    LLM 的系统设计

    • 算力成为了所有人的瓶颈（物理上的问题，GPU 再多也解决不了）

    Tokenizer

    • 为什么要用这玩意：token 比自然语言的词语更通用，比词语更短，好处理
    • Eg （Eggsample的简写 :b）: Byte Pair Encoding (BPE). Train steps:
      1. Take large corpus of text
      2. Start with one token per character
      3. Merge common pairs of tokens into a token
      4. Repeat until desired vocab size or all merged

    Lecture 3: Post-Training Verifiable Agents#

    提问：“Agentic” 模型与传统 LLM 的区别#

    • 早期聊天模型
      • 与人对齐
      • 被设计来最大化满足人类偏好
    • Agentic 模型
      • 与环境反馈对齐
      • 被设计来最大化完成可验证的成果（在满足人类偏好之外）

    早期模型被训练来成为优秀的聊天机器人

    早期模型的不足：

    • 对话不可验证，往往没有确定答案
    • 对话只需要跟用户交互
    • 可能一本正经地胡说八道
    • 需要跟更多实体（用户和环境）交互才可能理解完整状态

    如今的模型被训练成优秀的代理人（Agent）

    训练可验证的 Agentic 模型需要些什么？#

    • 第一步：优秀的、可验证的训练数据
    • 第二步：可验证的 Agent 应当是智能的。我们需要定义什么是智能
    • 第三步：把数据正确喂给模型的方法

    Agentic Models Maximaze Verifiable Reward

    • Point 1 - The Environment: 模型要消化告知当前环境信息和用户意图的 tokens。环境可能是代码 repo、网页浏览器等等
    • Point 2 - Tools: 模型要生成能被提供额外相关信息的软件工具消化的 tokens，来最大化从 verifier 处获取的正向奖励。软件工具可以是提供额外信息的 APIs 或能改变环境状态的工具
    • Point 3 - Verifier: 模型要生成能最大化从 verifier 处获取正向奖励的 tokens。Verifier 是代码、数学证明、网页的 DOM scripts 等测试单元
