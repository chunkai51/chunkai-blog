    Agent 到底是啥？我自己造一个看看

    March 17, 2026 · Chunkai

    一边补充着理论知识，一边直接开干，管他什么 LangChain，LangGrahp，SDK，tool-using，我先用 python 手写个 agent loop 感受一下这玩意是怎么搞出来的，应该没多难吧。

    构建过程#

    1. 设计工程结构#

    连搜带问，大概有了个眉目，agent 的核心目标是

    用户输入 LLM思考 选择工具 执行工具 返回结果 继续思考

    所以需要项目目录结构大概就是

    agent_project
│
├── agent.py        # agent loop
├── tools.py        # 工具实现
├── llm.py          # 模型调用
├── config.py       # API key等
└── requirements.txt

    在一个循环里调用 LLM，用 python 函数执行调用好的工具，再稍微管理一下上下文，这大概就是 agent loop 干的事情了。

    2. 调用大模型#

    首先，找一找我吃灰的百炼平台 api key，复制下来，大概包装一下，他们支持 OpenAI 兼容 API，帮助文档里写了好多，但我大概配一下就好

    llm.py:

    from openai import OpenAI
from config import key

client = OpenAI(
    api_key=key,
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1"
)

# 用来调用大模型的函数，传入消息和工具列表，返回大模型的回复
def call_llm(messages, tools):

    # 调用大模型接口，传入消息和工具列表，获取回复
    # 把一个表示大模型回应的复杂对象传给response
    response = client.chat.completions.create(
        model="qwen-plus-2025-07-28",
        messages=messages,
        tools=tools
    )

    # 返回大模型的回复，有时可能有多个候选，这样确保取了第一个
    return response.choices[0].message

    3. 定义工具#

    ChatGPT 建议搞个简单的工具，比如计算器，那这么简单的任务，会不会模型不用工具自己把问题解了也看不出来？先这么着吧

    tools.py:

    import math

# 通过调用math库里的某些神奇函数来计算输入的表达式
def calculator(expression: str):
    try:
        result = eval(expression)
        return result
    except Exception as e:
        return f"Error: {str(e)}"
    
# 定义工具的schema，供agent调用（这好像是json呢）
tools_schema = [
    {
        "type": "function",
        "function": {
            "name": "calculator",
            "description": "calculate math expression",
            "parameters": {
                "type": "object",
                "properties": {
                    "expression": {
                        "type": "string"
                    }
                },
                "required": ["expression"]
            }
        }
    }
]

    然后忽然说还需要一个 tool runner 来运行工具，于是又新建一个文件

    tool_runner.py:

    '''agent的工具运行器，负责根据agent的指令调用相应的工具并返回结果'''

from tools import calculator

# 定义工具的映射关系，方便根据工具名称调用对应的函数，因为当前只有一个工具，显得有点多余
tool_map = {
    "calculator": calculator
}

# 根据工具名称和参数调用相应的工具函数，并返回结果
def run_tool(name, args):
    func = tool_map[name]
    return func(**args)

    4.写 Agent Loop#

    终于到了最关键的一步！

    Agent loop 就是一个循环：

    Perception → Reason → Act → Observe → Repeat

    接收用户输入，调用LLM，执行工具，把结果再喂回LLM. 实现给 AI 脑、手、记忆。

    agent.py:

    '''agent的核心代码，负责与LLM交互，解析LLM的指令并调用工具运行器执行相应的工具函数'''

import json
from llm import call_llm
from tools import tools_schema
from tool_runner import run_tool

# 定义agent初始消息，告诉大模型它是个小蠢猫，但会使用工具
messages = [
    {"role": "system", "content": "You are an ignorant kitty cat but you can use tools."}
]

# 传说中的 agent loop
while True:
    
    user_input = input("Ask: ")

    # 把用户输入添加到消息列表中，准备发送给大模型
    messages.append(
        {
            "role": "user",
            "content": user_input
        }
    )
    
    # message 接收大模型的回复，这个回复可能包含工具调用的指令
    message = call_llm(messages, tools_schema)


    if message.tool_calls:

        tool_call = message.tool_calls[0]  # 目前只处理第一个工具调用指令

        # 工具名称
        name = tool_call.function.name  
        # 工具参数，原本是字符串格式的json，需要解析成字典
        args = json.loads(tool_call.function.arguments)  

        # 调用工具运行器执行相应的工具函数，并获取结果
        result = run_tool(name, args)  

        # 打印工具调用的细节，方便调试
        print(f"Tool call: {name} with args {args}, got result: {result}")

        # 把工具调用的结果作为工具消息添加到消息列表中，继续发送给大模型
        messages.append(message)

        messages.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": result
        })

    else:
        # 如果没有工具调用指令，直接把大模型的回复打印出来
        print(f"LLM response: {message.content}")

        # 把大模型的回复添加到消息列表中，继续发送给大模型
        messages.append(message)

    完成了！

    总结与思考#

    成果#

    我写成了我的第一个 Agent （我忘了让他说一句 Hello world 有点难受），通过调用百炼提供的 API Key，qwen plus 模型，OpenAI 库提供的框架，自己写的简单计算器工具和主循环来实现。

    思考#

    完成了这样的设计流程，我发现 agent 确实很好理解，怪不得都能简化到可以像 Scratch 一样搭建了。可以理解成把 LLM 当作大脑，给大脑接上手、记忆系统，甚至眼、耳、更多的能力，就是 LLM Agent。

    不足#

    我的主循环逻辑显然还存在问题（调用工具后没有回复、不能退出），工具也过于简陋，空有一个大模型在这卖萌真是辛苦它了。如果愿意投入，可以把这个东西做得更强大，毕竟可拓展性也很强。另外我用的是 OpenAI SDK，如果换成别的，可迁移性还得打个问号。

    其他收获#

    本次我为了确保自己上手做，没有用 coding agents，也没有复制粘贴。我在 ChatGPT 开了两个对话：一个用来指导构建，回答设计上的问题；另一个用来解释我看不懂的代码。这像是一种不错的学习方式，即便我还对 python 不太熟悉，也没有过大的困难，挺舒服。即便后面用 Coding Agents，也可以开两个线程来分开构建过程和回顾学习。

    下一步#

    现在我理解了 agent 的基本结构，可以随时随地手搓一个这样的简易 agent loop 了，这个项目可以先放着了。要带着本次收获的对 agent 的理解继续读新闻、博客、论文，听 lectures，学其他技术和理论时也要思考其与 agent 的关系。如果再做更像样的 agent 项目，我相信也能更得心应手。
