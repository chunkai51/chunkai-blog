    追了一圈各种小龙虾XXClaw，答案却藏在ChatGPT侧边栏：OpenAI Codex终于做好了“AI用电脑”这件事

    May 20, 2026 · Chunkai

    过去几个月，我像追连续剧一样追各种“xxClaw”“小龙虾”。

    OpenClaw、CoPaw、QClaw、QoderWork、WorkBuddy……名字一个比一个像能从桌面角落里爬出来帮我打工。最开始体验OpenClaw时最兴奋，那是过年那会儿，我把 OpenClaw 接上钉钉，然后用手机给它发消息，让它在实验机上整理文件、处理桌面任务。

    在当时，那个瞬间确实很有未来感。

    人在海滩上打扑克，电脑在城市的另一边，AI 在那里默默操作文件。以前说“AI 使用电脑”总觉得像 demo，直到我真的在手机上发一句话，回头看到实验机上的任务做完了，才觉得这东西离现实不远。

    但也是那一周，我开始对 OpenClaw 这类桌面智能体冷静下来。

    它方向很有前景，但问题也暴露得很清楚：权限怎么给？成本怎么控？它凭什么碰我的文件、浏览器、账号、密钥？出了错谁负责？一个普通用户到底应该把多少电脑交给它？

    当时我写 OpenClaw 的结论，大概是：它不是答案，但它让答案变得可见。

    结果兜兜转转几个月之后才发现，这个“答案”不是我追着看的各种小龙虾换壳版，而是曾经藏在 ChatGPT 侧边栏里很不起眼的 Codex。

    更准确地说，是最近几个月更新之后的 Codex App。

    Codex 一开始压根儿不是干这个的#

    Codex 并不是新东西。

    2025 年 5 月，OpenAI 发布 Codex，当时官方描述是一个 cloud-based software engineering agent。它可以在 ChatGPT 侧边栏里接收编码任务，跑在独立云沙箱里，读写代码文件，运行测试、linter、type checker，然后把结果提交给你审查。

    那时候我对它的感受差不多是：“哦，ChatGPT 里面多了个能帮忙改代码的远程工位，不过我写代码有 cursor 啊，用不着这个。”那时日子就这么惬意，除了新模型好像就没什么能在科技圈掀起波澜的。

    能让我感到兴奋的是 25 年底横空出世的 OpenClaw 这样更刺激的东西：能操作桌面，能接聊天平台，能像一个系统用户一样去完成任务。虽然粗糙，但有一种很强的冲击力。

    所以后来我追 OpenClaw，追腾讯的 WorkBuddy/QClaw，甚至研究豆包手机、Galaxy AI、AppFunctions 这些路线时，也完全没有把 Codex 当成同一张桌子上的玩家。不过倒是用上了 Codex：此时大家都开始脱离 IDE 使用 Claude Code 这样的命令行 AI 工具来写代码，而我那时也想赶潮流，却还不太会用命令行，既有 CLI 端又有桌面端 App 的 Codex 便被我作为 Claude Code 的替代品。

    Codex 就这样在我眼皮子底下从一个用途相对窄的编码智能体开始，把功能从命令行、MCP、Skills、多 Agent，加到了到自动化、跨 App、使用浏览器，甚至开始长出鼠标用电脑、连接手机远程控制。

    4 月那次更新，Codex 开始离开代码编辑器#

    关键节点是 2026 年 4 月 16 日。

    OpenAI 发了一篇官方博客：Codex for (almost) everything。

    OpenAI 说，Codex 现在可以：

    • 用 background computer use 在 Mac 上看、点、输入，有自己的 cursor；
    • 多个 agent 可以在 Mac 上并行工作，不影响用户继续用别的 App；
    • 用 in-app browser 让用户直接在网页上评论，给 Codex 指出前端或游戏里的问题；
    • 用 gpt-image-1.5 生成和迭代图片；
    • 接入 90 多个 plugins，把 skills、App integrations 和 MCP servers 组合起来；
    • 用 automations 处理持续、重复的工作；
    • 通过 memory 记住偏好、纠正和之前收集过的上下文。

    这些东西堆在一起，我的第一反应是：等等，这不就是我当时折腾 OpenClaw 和 QoderWork 时一直想要的那套东西吗？

    但我之前用这些桌面智能体不爽的地方，并不是纠结“它能不能动鼠标”。

    能动鼠标其实只是开始，更麻烦的是它动鼠标的时候有没有边界，任务能不能持续，出错时我能不能接管，长期任务会不会丢上下文，能不能调用更稳定的工具而不是每次都靠视觉和点击硬走。

    OpenAI 这方面拿得很准，给我的感觉是：Codex 的“AI 用电脑”终于不再是个酷炫的 demo，他们是有在往工作流里塞一套相对完整的系统的。

    这点很重要，因为纯粹的 computer use 很容易让人火大。

    你看到 AI 自己打开 App、点击按钮、填表单，第一反应肯定是“我靠，这不就是未来吗”。但多试几次就会发现，视觉操作本身又慢又脆。按钮位置变了，页面加载慢了，弹窗多了一个，登录态没了，整个流程就可能歪。

    而 Codex 的 computer use 在我看来更像一种补位能力。

    OpenAI 的文档里也写得很清楚：如果目标 App 有专门的 plugin 或 MCP server，应该优先用结构化集成；只有在 Codex 需要视觉检查或操作 App 时，再用 computer use。官方文档还特别提醒，computer use 会影响项目 workspace 之外的 App 和系统状态，所以要把任务限定清楚，并认真看权限提示。

    这就比“我直接看屏幕模拟人类”成熟很多。

    它给了 AI 一双手，但同时也在给它装刹车。

    AI 能用电脑已不稀奇，难的是让人敢用#

    我之前对 OpenClaw 的担心，大概有三类。

    第一是安全。

    桌面智能体只要能碰系统，就不再是普通聊天机器人。它看到的不只是你输入的问题，还可能是你的文件、浏览器页面、登录状态、剪贴板、弹窗，甚至一些你自己都没意识到已经打开的东西。

    OpenClaw 让我兴奋，也让我不太敢把它放进主力电脑。

    所以那次实验我们用了隔离机，后来还用了云电脑。安全是安全了一点，但代价是另一个问题：它接触不到我真正有价值的工作环境。

    这就很矛盾。

    你不给它权限，它干不了什么大事；你给它权限，又会觉得心里发毛。

    而 Codex 的做法至少是在把这个矛盾拆开。

    根据 Codex computer use 文档，它在 macOS 上需要 Screen Recording 和 Accessibility 权限。macOS 系统权限决定它能不能看和操作 App，Codex 自己的 app approval 决定它能用哪些 App，文件读写和 shell 命令还继续受 sandbox 和 approval 设置约束。

    也就是说，这不是一个总开关。

    它把“看屏幕”“点按钮”“读写文件”“跑命令”“使用某个 App”拆成了不同层次。

    当然，这不代表它没有风险。官方也提醒，如果 Codex 使用你的浏览器，它可以操作你已经登录的网站；网页里的恶意或误导内容也可能影响它的操作。说白了，你让它点出去的东西，在网站看来就是你的账号点出去的。

    但至少这里的风险被摆到了桌面上，每一次有风险的尝试，Codex 都要向用户确认，如果选择自动审查模式，也通常卡得很到位。这和我之前玩开源桌面智能体时的感觉不太一样。那时候很多风险藏在“能跑起来就行”的兴奋里，权限边界全靠自己想象。

    第二是成本。

    桌面智能体很吃 token，也很吃时间。

    它不是普通聊天，一问一答就完。它要观察、计划、调用工具、读文件、执行命令、看结果、再改计划。你给它一个看起来很小的任务，背后可能跑出几十轮上下文。

    我当时一周花掉 500 多美元，确实有抱怨贵，但重点在于想不通它凭什么这么贵。

    Codex 也没有神奇地解决成本问题。事实上，agent 真正干活之后，使用限额和计算成本只会更敏感。Axios 在报道 Codex mobile 时也提到，更多 Codex 使用意味着更多 compute，而 compute 正是 AI 实验室最宝贵的资源之一。

    但 Codex 至少在改变交互节奏。

    OpenAI 的 Automations 文档 里，已经把 recurring tasks、Triage inbox、thread automations 这些东西做进了 Codex。你可以让它定期检查某个项目、跟进 PR、轮询 Slack 或 GitHub，也可以让一个线程按固定节奏醒来继续处理长任务。

    它开始承认：agent 不应该只在你盯着屏幕的时候工作。

    你给它一个任务，它跑一段，卡住了叫你；你有空时给它一个方向；它继续跑；最后把结果放进 inbox。

    这个工作方式和传统软件不太一样，和雇一个人也不完全一样。更像是在和一个不太稳定但很能干的实习生协作。你不应该完全放手，但也不必每一步都站在旁边。

    第三是泛用性不足。

    桌面智能体最容易让人产生幻想：它都能用电脑了，那不是啥都能干？

    真不是。

    我之前让 OpenClaw 自动发公众号文章，就被现实教育了一遍。微信后台那套前端交互，对自动化极其不友好。重复按钮、复杂编辑器、封面图设置、扫码验证、弹窗确认，每一步都可能翻车。

    这让我当时得出一个判断：agent 的“最后一公里”不是被模型卡住，而是被现有软件生态卡住。

    现在看 Codex，我觉得 OpenAI 也在绕这个坑。

    如果有结构化入口，就用插件、MCP、Apps SDK；如果没有，就用 browser 或 computer use 补。2025 年 10 月，OpenAI 发布 Apps in ChatGPT 和 Apps SDK，说 Apps 可以自然出现在 ChatGPT 对话里，开发者可以基于 MCP 定义应用逻辑和界面。Booking.com、Canva、Coursera、Expedia、Figma、Spotify、Zillow 是当时的首批伙伴。

    这件事和 Codex 是连着的。

    如果以后越来越多服务变成 ChatGPT 里的 App 或 Codex 的 plugin，AI 就不需要每次都假装成人类去点网页。它可以直接调用更稳定的接口，拿到更清晰的上下文，也更容易做权限控制。

    所以我现在看 computer use，也不觉得它应该成为终点。

    它是桥，在真实世界还没给 AI 留出入口的时候，Codex 可以先从屏幕和鼠标进去。但厂商们最终想做的，应该是让这些入口逐渐变成正式的门，而不是一直翻窗。

    Codex Mobile 让我想起当时用钉钉遥控 OpenClaw#

    如果说 4 月更新让 Codex 有了“手”，那 5 月 14 日的更新，就是让它有了“遥控器”。

    OpenAI 发布 Work with Codex from anywhere，宣布 Codex 进入 ChatGPT mobile app preview。

    官方说，现在每周已经有超过 400 万人使用 Codex。用户可以用 iOS 或 Android 上的 ChatGPT mobile app，连接一台正在运行 Codex app 的 Mac。手机端加载的是那台主机上的 live state，你可以在手机上开始新线程、继续旧线程、回答问题、改变方向、审批命令、切换模型、查看输出、diff、测试结果、终端输出和截图。

    文件、凭据、权限和本地配置仍然留在运行 Codex 的机器上。

    底层则通过 secure relay layer，让受信设备可以跨设备访问，但不把机器直接暴露到公网。

    这段读下来，我第一时间想到的就是我之前用钉钉遥控 OpenClaw 的体验。

    区别在于，当时那条链路是我自己拼出来的：

    手机 -> 钉钉 -> OpenClaw -> 实验机/云电脑。

    能用，很酷，但也很草台。配置、权限、安全、上下文同步，基本都要自己想办法。

    现在 OpenAI 把类似体验放进了 ChatGPT 手机 App 里：

    手机 -> ChatGPT -> Codex host -> 本地/远程工作环境。

    这就不只是“手机上也能写代码”了。

    TechRadar 对这次更新的标题说得很直白：ChatGPT mobile app now serves as a Codex controller。Axios 也把重点放在 mobile access 可以 review outputs、make approvals、start new tasks。

    Codex Mobile 不是要你在手机上认真写代码。没人想在地铁上用手机看五百行 diff，把眼睛看成小夜灯。

    它更像一个远程值班界面。你在路上突然想到一个任务，可以丢给 Codex。它跑着跑着需要确认，你在手机上看一眼，批一下。它发现两种方案，你选一个。它跑完测试，给你看结果。等你回到电脑前，事情已经往前走了一截。

    这和我之前说“手机遥控电脑”的理念很一致，而且这个是真的能稳定高效使用的。因为它不是把整台电脑简单投到手机上，而是把 agent 协作里最需要人的几个节点摘出来：发起、转向、审批、验收。

    这才是手机端适合做的事。

    厂商们其实都在回答同一个问题#

    当然，OpenAI 不是第一个意识到这件事的公司。

    Anthropic 早就在往这个方向走。TechRadar 在 2026 年 2 月报道过 Claude Code 的 Remote Control，说它让开发者可以从手机、平板或浏览器远程控制本地 Claude Code session。那篇报道还强调，Remote Control 更像本地 CLI session 和 Claude mobile/web 界面之间的同步层。Claude Cowork 也在做更广义的工作智能体，不只是写代码。

    腾讯这边则更接地气。不管是 WorkBuddy、QClaw，还是之前围绕 OpenClaw 做的一键部署和“养虾”服务，腾讯抓的是另一件事：让普通用户真的能上手。你可以说这不够优雅，但切切实实跑完了“最后一公里”。很多时候，产品差距不是模型差一点，而是用户卡在安装、登录、模型配置、权限、云电脑、聊天入口这些地方，腾讯这类路线的意义在这里。它证明桌面智能体要普及，不能只靠 GitHub README 和酷炫 demo。要有人把部署、入口、模型、计费、客服、企业账号都接起来。

    所以这篇文章不是要说 OpenAI 已经赢了。

    我想说的是，厂商们都开始思考：

    当 AI 真的开始使用电脑时，人应该站在哪里？

    OpenClaw 的答案是：你自己部署，你自己承担。

    腾讯的答案是：我帮你装好，放进我的云和 IM 生态。

    Anthropic 的答案是：让 Claude Code/Cowork 继续工作，你从远处接管。

    OpenAI 的答案是：把它放进 ChatGPT、Codex app、mobile、plugins、Apps SDK 这一整套系统里。

    这几个答案没有谁完全胜过谁，但 OpenAI 这次让我意外的地方在于，它补齐了一整套控制面，我不用额外安装 App、调通链路，直接用手机上本就使用频率很高的 ChatGPT App 就能优雅控制 Codex，完成我在电脑上的许多事务，体验甚至比让 ChatGPT 帮我创建 Apple Music 歌单都顺滑。

    我之前担心的问题，OpenAI 也在产品里思考#

    写到这里，我更能解释那种“答案藏在 ChatGPT 侧边栏”的惊喜感了。

    我当时看 OpenClaw，就一直在想它该怎么进入日常。

    一个能操作电脑的 AI，如果要进入日常，至少要回答这些问题：

    • 它在哪里运行？
    • 它能看到什么？
    • 它能点什么？
    • 它能改什么文件？
    • 它什么时候要问我？
    • 我不在电脑前时怎么介入？
    • 它怎么记住之前做过的事？
    • 它怎么调用 App 和服务，而不是每次都硬点 UI？
    • 它长期跑任务时，结果放在哪里给我看？

    这些问题，OpenAI 最近几个月都在 Codex 里陆续给出产品答案。

    不一定都完美。

    比如 computer use 目前主要是 macOS，欧洲部分地区启动时不可用；手机连接也要求 host 在线、醒着、运行 Codex；如果你让它碰已经登录的网站，风险仍然是你的；automations 在 full access 下也会有更高风险。

    这些都不是小事。

    但至少不再是把 AI 放进电脑，剩下靠用户自己祈祷。

    Codex 现在更像一个有权限体系的工作台。它能用 shell，也能用浏览器；能接插件，也能在必要时看屏幕；能本地跑，也能接远程环境；能在桌面上工作，也能让你从手机上审批；能做一次任务，也能按节奏醒来继续。

    这才让我觉得，OpenAI 这次终于把“AI 用电脑”这件事做得有点像产品了。

    AI 早就在用电脑了，从浏览器自动化、RPA、Claude Computer Use，到 OpenClaw、豆包手机、各种 CUA，大家都在让模型看屏幕、点按钮、操作环境。Codex 不是第一个做到，但它开始把这件事放进一个更完整的用户入口、权限模型和应用生态里。

    这就像从“能开车跑”变成“有方向盘、刹车、保险、导航、路权和停车位”，没有这些，能开也不太敢坐。

    Codex 的野心，可能不只是程序员#

    现在 Codex 还带着很强的开发者标签。

    这很合理。

    代码是最适合 agent 的早期场景之一：文件结构清楚，有测试，有版本控制，有 diff，有 review，有明确的对错反馈。一个 agent 在这里犯错，至少还能用 git、test、CI 把它拦住。

    但 Codex 最近的更新已经明显越过了纯代码边界。

    OpenAI 官方在 4 月那篇文章里写，Codex 可以和更多日常工具、App 一起工作，可以生成图片，可以记住偏好，可以承担持续和重复的工作。插件列表里也不只是代码工具，还包括 Microsoft Suite、Atlassian Rovo、Neon、Render、Remotion 这类开发和工作流入口。

    这让我想到之前我写 App 会不会被 AI 干掉那篇文章时的判断：大部分任务型 App 可能会慢慢退到后台，变成服务。用户不一定还要打开每个 App，agent 会替你在中间调度。

    Codex 现在走的也是类似路线。

    只是它从开发者工作台开始。

    ChatGPT 是前台入口，Apps SDK 和 plugins 是服务连接层，Codex 是那个能真的去执行、修改、验证、汇报的 agent。

    如果这条路继续往前走，Codex 就可能从一个写代码的工具变成 ChatGPT 生态里最先长成熟的一类高权限工作 agent。

    这也是我这次比较愿意肯定 OpenAI 的地方。

    它没有只做一个漂亮 demo，告诉用户“你看，AI 会点鼠标了”。

    它在做生态：ChatGPT app 负责随时介入，Codex app 负责多 agent 工作台，plugins 和 Apps SDK 负责连接服务，computer use 负责补没有接口的最后一公里，automations 负责让任务持续跑。

    这个组合目前看来足够扎实。

    写在最后#

    我追了一圈各种小龙虾，最后发现答案早藏在了 ChatGPT 侧边栏里，这事多少有点滑稽，但也说得通。

    OpenClaw 这样的开源项目负责把未来先演出来。它不优雅，不稳定，也不够适合普通用户，但它让很多人第一次意识到：AI 不一定只待在聊天框里，它可以作为一个电脑用户存在。

    我很喜欢 OpenClaw 的地方也在这里。

    它不是终点，但它把问题暴露得很完整。

    而 Codex 开始认真处理这些问题：安全边界、远程介入、长任务、插件生态、桌面操作、手机审批、企业治理。

    这些东西听起来没有“AI 自己点外卖”那么刺激，但它们决定了一个桌面智能体能不能从 demo 进入日常。

    所以 Codex 从一个侧边栏云端小功能，变成了与 Claude Code 平起平坐的编程智能体，最后成为 OpenAI 用来试验下一代工作入口的地方，是有迹可循的。Codex App 上线时科技圈的看好是有预见性的。

    如果说 OpenClaw 让我第一次看到“AI as OS User”这件事的冲击力，那 Codex Mobile 和 computer use 让我第一次觉得，这件事有可能被做成一个普通人敢用、公司也敢管的产品。

    当然，我还不会在主力电脑上完全给它打开权限。

    但我会开始认真考虑，哪些任务可以先交出去，哪些 App 可以先开放，哪些权限可以一点点试，这可能才是桌面智能体真正进入日常的方式。

    从一个低风险任务开始，让它做，让它报错，让它问你，让你审批，然后一点点扩大边界。

    以前这像是在养一只不太听话的小龙虾。

    现在看 Codex，我觉得 OpenAI 至少开始给它准备笼子、饲料、遥控器和说明书了。
